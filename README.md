# NordPerms

Небольшой провайдер прав для **Paper/Folia 26.2, Java 25**. Один JAR для обеих платформ. Две группы: `players` и `moderators`. Без базы данных, телеметрии, веб-редактора и сетевых запросов самого NordPerms.

Это не форк и не полная замена всех возможностей LuckPerms. Совместимость рассчитана на стандартные Bukkit/Paper-проверки прав, которыми пользуются собственные Nord-плагины. На боевом сервере плагин автоматически ничего не устанавливает и не мигрирует.

## Настройка

1. На остановленном сервере сохраните резервную копию LuckPerms, его данных и всех рабочих конфигов. Не удаляйте базу авторизации NordAuth.
2. Заранее выпишите необходимые точные разрешения. Автоматического переноса групп/контекстов/UUID из LuckPerms нет.
3. Уберите JAR LuckPerms из активной папки `plugins`, сохранив его для отката. Не запускайте два провайдера прав одновременно.
4. Установите релизный JAR NordPerms. После первого старта он создаст `plugins/NordPerms/config.yml` с пустым списком модераторов.
5. Заполните конфиг своими значениями. Учётная запись NordAuth должна **уже существовать и быть защищена паролем до назначения модератором**. Используйте UUID, фактически видимый сервером, а не UUID, угаданный по имени или с сайта.
6. Выполните в консоли `nordperms reload`. В игровой записи это обычно обозначается `/nordperms reload`, но управление из чата намеренно запрещено даже модераторам. `nordperms status` показывает состояние.

Минимальный пример структуры (UUID ниже — фиктивный, не копируйте его как настоящий):

```yaml
schema-version: 1
groups:
  players:
    permissions:
      nordregen.use: false
      nordauth.admin.resetpassword: false
      nordcommands.bypass: false
  moderators:
    permissions:
      nordregen.use: true
      nordauth.admin.resetpassword: true
members:
  "00000000-0000-0000-0000-000000000001": moderators
```

Полный поставляемый шаблон также запрещает OP/deop, Bukkit reload и обходы NordCommands/NordFireworks. Не заменяйте его сокращённым примером без проверки остальных разрешений. `nordregen.use` разрешает нынешнюю команду очистки лаг-механизмов `/regenchunk`, а не восстановление ландшафта.

`moderators` наследует `players`; явные значения модератора переопределяют значения игроков. Права, добавленные только модераторам, автоматически запрещаются обычным игрокам и неавторизованным модераторам. `*`, `plugin.*`, имена вместо UUID, строки вместо boolean и дубликаты YAML-ключей не принимаются. Разрешения пишутся полностью и строчными буквами. Неуказанные права сохраняют обычную семантику Bukkit defaults/attachments; это не глобальный запрет всего игрового функционала.

## Защита и отказы

- Проверки идут по неизменяемому снимку в памяти. Перечитывание файлов выполняется отдельно от игровых потоков; успешная публикация снимка снимает права у всех подключённых игроков без ожидания их обхода. Обновление отображаемых команд выполняется на потоках игроков.
- Ошибка при `reload` оставляет предыдущую рабочую политику. Ошибка начального конфига запрещает новые входы, пока администратор не исправит файл и не перечитает его из консоли.
- На `online-mode=false` права модератора доступны только после подтверждённой сессии NordAuth. Проверен NordAuth **1.3.0**; узкий мост использует его метод проверки сессии. Отсутствие/отключение NordAuth, несовпадение метода или ошибка проверки закрывают привилегии. При `online-mode=true` без NordAuth доверенным источником UUID служит проверка Minecraft. Другие авторизаторы пока не поддерживаются.
- Первая регистрация уже назначенного модераторского UUID запрещена. Сначала зарегистрируйте обычную учётную запись, затем назначьте роль. Нельзя считать имя или сам UUID доказательством авторизации в offline-режиме.
- Модераторы могут сбрасывать пароль только **онлайн-игрокам без роли модератора**. Собственный пароль, пароль другого модератора и офлайн-аккаунты восстанавливаются только из консоли. Проверяются также namespaced-варианты команды. Самостоятельная обычная смена пароля через NordAuth с проверкой старого пароля не изменяется.
- OP-аккаунты не допускаются на сервер: роль выдаётся конфигом, не через OP. NordPerms не меняет `ops.json`. Не выдавайте OP во время работы; консоль и установленные серверные плагины считаются доверенными.
- Если другой провайдер уже заменил систему прав игрока, вход/работа не продолжаются с небезопасными правами по умолчанию. Горячее отключение NordPerms приводит к остановке сервера. Не используйте PlugMan, `/reload` и горячую замену JAR.

Провайдер прав не является античитом и не защищает от уязвимого/вредоносного серверного плагина, доступа к консоли/файлам, небезопасного прокси или скомпрометированного пароля. Команды, которые вообще не проверяют права, необходимо исправлять в предоставляющем их плагине. Перед заменой LuckPerms проверьте также права на прокси: этот JAR работает только на игровом сервере.

## Совместимость и производительность

Поддерживаются `hasPermission`, `isPermissionSet`, `getEffectivePermissions`, стандартные и временные `PermissionAttachment`, зарегистрированные Bukkit parent/children и регистронезависимые проверки. Явная серверная политика имеет приоритет над attachments других плагинов. Несогласованное наследование запрещает право; явный узел переопределяет наследование. После динамического изменения дерева разрешений сторонним плагином выполните `nordperms reload`.

Не реализованы LuckPerms API/команды, Vault, контексты, префиксы, временные группы, wildcard-права и отдельный провайдер Velocity. Плагин, который требует LuckPerms/Vault напрямую, не становится совместимым автоматически. NordCommands остаётся независимым фильтром команд; его конфиг не предоставляет реальные права.

Внутри используется однократное подключение к `CraftHumanEntity.perm`, аналогичное по месту интеграции LuckPerms. Структура поля проверяется; нет `Unsafe` и изменений самого ядра. Это внутренняя часть сервера: совместимость с **новой версией ядра должна проверяться отдельно**, а не предполагаться по `folia-supported: true`.

Архитектура рассчитана на частые проверки: общие неизменяемые карты двух групп, набор UUID и отсутствие файлового/сетевого ввода-вывода на игровом пути. Нет постоянного обхода 600 игроков и таймера пересчёта ролей. Тест 600 синтетических UUID и замер проверки прав — не доказательство TPS при 600 реальных игроках. Проверки и ограничения описаны в [TESTING.md](TESTING.md).

## Сборка

```text
mvn -B -ntp verify
```

Результат: `target/NordPerms-1.0.0.jar`. GitHub Actions собирает и запускает модульные тесты на Java 25. В репозитории только обезличенные шаблоны и тестовые данные. Серверный `plugins/NordPerms/config.yml` не нужно копировать сюда.
